# Интерактивный обработчик задач (Очередь задач)

## Описание
Проект представляет собой платформу обработки задач, построенную по принципам **Чистой Архитектуры**. Проект является продолжением разработки доменной модели и добавляет возможности **ленивой обработки**, **итераторов** и **генераторов** для управления коллекциями задач.

Основная цель работы — разработка очереди задач (`TaskQueueInMemory`), которая обеспечивает:
*   **Ленивую фильтрацию**: Использование генераторов (`yield`) для фильтрации без избыточного выделения памяти.
*   **Протокол итерации**: Реализация магических методов (`__iter__`) для совместимости со стандартными конструкциями Python (`for`, `list()`).
*   **Повторный обход**: Возможность многократно итерироваться по коллекции без потери данных за счет создания новых итераторов по внутреннему контейнеру.
*   **Агрегацию данных**: Поддержка встроенной функции `sum()` для подсчета общих параметров за счет реализации `__add__` и `__radd__` в доменной модели.
*   **Защиту инвариантов**: Продолжение использования дескрипторов (`__get__`, `__set__`) и свойств (`@property`) для инкапсуляции и валидации атрибутов.

Структура проекта строго разделена по слоям:
*   `domain`: Ядро системы. Содержит бизнес-сущности (`Task`), правила валидации и исключения. Не зависит от внешних библиотек.
*   `usecases`: Прикладная бизнес-логика. Содержит интерфейс-контракт коллекции (`TaskQueue`) и класс `QueueService`, инкапсулирующий CRUD-операции.
*   `repository`: Реализация доступа к данным. Содержит класс `TaskQueueInMemory` — коллекцию задач на базе списка (`list`), реализующую все протоколы итерации и генерации.
*   `adapters`: Внешние интерфейсы. CLI взаимодействует с пользователем и передает команды в `ActionOrchestrator`, который координирует вызовы к слою `usecases`.

## Особенности реализации (Коллекции и Генераторы)
*   **Итератор Очереди**: Класс `TaskQueueInMemory` реализует метод `__iter__`, который возвращает итератор по внутреннему списку, а также поддерживает функции `len()` и поиск максимума.
*   **Ленивые фильтры**: Методы `filter_by_status`, `filter_by_priority` возвращают генераторы. Метод `get_task_by_id` прерывает поиск, как только нужный элемент найден.
*   **Совместимость с sum()**: В классе `Task` реализованы Dunder-методы сложения, что позволяет выполнять конструкции вида `sum(queue.filter_by_status(1))`.

## Пользовательские дескрипторы
В проекте используются reusable-компоненты для валидации:
*   `PriorityValidator`: Data descriptor, проверяет, что приоритет — целое число от 1 до 5.
*   `DescriptionValidator`: Data descriptor, гарантирует, что описание — непустая строка.
*   `StatusInfoDescriptor`: Non-data descriptor, демонстрирующий механизм перекрытия атрибутов.
*   `FilePathValidator`, `TaskCountValidator`: Валидаторы для ввода данных в CLI.

## Основные используемые библиотеки
В проекте использовались следующие библиотеки:
- **questionary** - создание красивого интерактивного меню в командной строке.
- **pytest & pytest-cov** - фреймворк для написания юнит-тестов и проверки процента покрытия кода.
- **mypy** - статический анализатор для строгого контроля типов.
- **ruff** - линтер и форматтер кода.

## Установка и запуск

Клонирование репозитория
```bash
git clone https://github.com/moonshyXD/TaskQueue
```

Перейдите в папку с репозиторием:
```bash
cd TaskQueue
```

Установите зависимости с помощью пакетного менеджера `uv`:
```bash
make build
```

Активируйте виртуальное окружение:
```bash
source .venv/bin/activate
```

Для запуска приложения:
```bash
make run
```
ИЛИ
```bash
uv run main.py
```

## Тестирование и Линтинг

Для запуска тестов (pytest):
```bash
make test
```

Для проверки покрытия кода:
```bash
make testcover
```

Для запуска линтера:
```bash
make lint
```
